# 새 릴리스 태그 생성 및 푸시

1. `${CLAUDE_PROJECT_DIR}`를 작업 디렉터리로 사용한다. 모든 검사와 Git 명령은 이 디렉터리에서 실행한다.
2. `package.json`의 최상위 `version`을 읽고, 정확히 `v{version}` 형식으로 태그 이름을 정한다. 예를 들어 버전이 `0.0.4`이면 태그 이름은 `v0.0.4`이다. 버전이 없거나 문자열이 아니거나 유효한 Git 태그 이름을 만들 수 없으면 중단하고 이유를 보고한다.
3. 태그를 만들기 전에 다음 조건을 모두 검사한다. 하나라도 충족하지 않으면 아무 태그도 만들거나 푸시하지 않고 중단한다.
   - `git status --porcelain` 출력이 없어 작업 트리가 깨끗하다.
   - `origin` 원격 저장소가 존재한다.
   - 같은 이름의 로컬 태그가 없다.
   - `git ls-remote --exit-code --tags origin "refs/tags/{태그 이름}"`으로 확인했을 때 같은 이름의 원격 태그가 없다. 종료 코드 2는 태그가 없다는 뜻으로 처리하고, 그 밖의 조회 실패는 중단한다.
4. 현재 `HEAD`에서 도달 가능한 가장 최근의 `v*` 태그를 기준 태그로 선택한다. 기준 태그가 있으면 그 태그 이후부터 `HEAD`까지의 커밋과 diff를 조사하고, 없으면 전체 커밋 기록과 현재 트리를 조사한다.
5. 조사한 실제 변경 사항만 사용해 한국어 CHANGELOG 형식의 태그 본문을 작성한다. 본문 첫 줄은 태그 이름으로 하고, 이후에는 `## Added`, `## Changed`, `## Fixed`, `## Removed`, `## Documentation`, `## CI` 중 해당하는 섹션만 둔다. 각 항목은 `- `로 시작하며 사용자 관점에서 구체적으로 작성한다. 빈 섹션, 커밋 해시 나열, 추측한 변경 사항은 포함하지 않는다. 릴리스할 변경 사항을 찾지 못하면 중단한다.
6. 작성한 본문 전체를 사용자에게 보여준 뒤, 그 본문으로 현재 `HEAD`에 주석 태그(annotated tag)를 로컬에 생성한다. 임시 메시지 파일을 사용해 `git tag -a "{태그 이름}" -F "{메시지 파일}"`을 실행하고, 생성된 태그 본문이 작성한 본문과 일치하는지 확인한 다음 임시 파일을 삭제한다. 생성 또는 검증에 실패하면 푸시하지 않고 오류를 보고한다.
7. 로컬 태그를 만든 뒤, 푸시하기 직전에 AskUserQuestion을 사용해 `이 태그를 origin에 푸시할까요?`라고 명시적으로 확인한다. 질문에는 태그 이름, 대상 `origin`, 태그 본문 전체를 포함한다. 명시적으로 승인받기 전에는 어떤 푸시 명령도 실행하지 않는다.
8. 사용자가 거절하면 로컬 태그는 그대로 두고 푸시하지 않았다고 보고한다. 사용자가 승인하면 `git push origin "refs/tags/{태그 이름}"`으로 해당 태그 하나만 푸시한다. `git push --tags`, 브랜치 푸시, 커밋 생성은 하지 않는다.
9. 푸시 후 `git ls-remote --tags origin "refs/tags/{태그 이름}"`으로 원격 태그를 확인하고, 태그 이름과 푸시 결과를 보고한다.
